# 測定用メジャー EPUB（画像位置・余白のずれをピクセルで測る）

画像の四辺に 0–100% の目盛りを焼き込んだサンプル本。リーダーで表示したスクショと
目盛りを突き合わせれば、画像や本文ボックスが「どちら側へ何px / 何%ずれ・欠けているか」
を目視ではなく数値で測れる。

## 中身
- `ruler-measure.epub` … ビルド済みの本（アプリの「開く」で読み込める。`spike-readium/Resources/` にも同梱済み）
- `make_ruler.py` … 目盛り画像ジェネレータ（Pillow）。`python3 make_ruler.py <出力先>` で3枚生成
- `png/` … 生成済み目盛り画像（portrait 3:4 / landscape 4:3 / square 1:1）。
  `src/OEBPS/images/small-logo.png`（140×90）は「拡大しない」ことを確かめるための小画像
- `src/` … EPUB のソースツリー（`zip` し直せば再ビルド可）
- `probe.html` … ブラウザ実測用。アプリが注入している img ルールを再現し、`getBoundingClientRect` で
  画像の実バウンディングボックスと四辺の隙間(gaps)を JSON で吐く

## 本の構成（spine, rtl）
1. 使い方
2. 縦長 3:4 メジャー
3. 横長 4:3 メジャー
4. 正方形 1:1 メジャー
5. 余白測定ページ（body ボックスを水色背景+青枠で可視化、四隅に赤字マーカー）
6. 本文＋挿絵（横長 4:3 を本文の途中に1枚）… 画像を高さいっぱいに拡大する処理が、本文の
   あるページでも比率を保ち、幅からはみ出さず、前後の本文を壊さないかを見る
7. 小さい画像は拡大しない（140×90 のロゴをブロック配置と行内配置で1枚ずつ）… ロゴ・飾り罫まで
   引き伸ばしていないかを見る
8〜12. 見開きの組み方（縦長・縦長・**横長**・縦長・縦長）… 画像だけのページが続く区間で
   2枚ずつ組になること、横長は単独で1見開きを占めること、そこから先の組が1つずれることを見る

## メジャー画像の読み方
- 赤い外枠 = 画像の物理的な端。枠が画面外に切れていれば、その辺がクロップされている
- 上辺/左辺の数字 = 0–100%。ずれ量は「隙間px ÷ 画像表示px × 100」で%に換算できる
- 緑の十字 = 画像中央。ビューポート中央と一致していれば中央寄せ成立
- 四隅 TL / TR / BL / BR = どの角が画面のどこに来たかで寄り方向が分かる

## 実測手順（ブラウザ / Playwright、file:// は不可なので HTTP 経由）
```bash
cd test-assets/ruler
cp probe.html src/OEBPS/
cd src/OEBPS
python3 -m http.server 8791
# 別ペインのブラウザで http://127.0.0.1:8791/probe.html を開く
```
`probe.html` は `window.__probe` に `{viewport, imgRect, gaps, natural}` を残す。
Playwright なら `browser_evaluate(() => window.__probe)` でそのまま読める。

## この道具で見つかること（実例）
- **中央寄せしたつもりが効いていない**: 縦書き(vertical-rl)で `object-fit:contain` は無力。
  img 要素自身が中身のサイズまで縮むので余白を埋めておらず、ブロックの開始位置＝右上に貼り付く。
  目盛りを見れば「left だけに隙間があり、右上にピン留めされている」と一目で読める
  （実測例: 900×1200 ビューポート・縦長3:4画像で left 90px / top 0 / right 0 / bottom 120px）。
  直すには img を包むブロックを画面いっぱいにして中央寄せする（`display:flex` + `align-items/justify-content:center` 等）。
- **ブラウザとアプリで結果が違う**: `position:fixed; inset:0` は Chromium(Playwright)では完全中央になるのに、
  縦書きの WebKit では画像が画面外へ飛ぶことがある。
  → **ブラウザで測った結果は、必ずこの本を実機（WKWebView）で開いて裏取りすること。**
