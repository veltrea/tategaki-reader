# tategaki-reader

**他の言語で読む:** [English](README.en.md)

日本語の縦書き EPUB を「とりあえず無難に読める」状態で表示し、VOICEVOX / AivisSpeech で読み上げる macOS（Mac Catalyst）向けのリーダーです。

---

## なぜ作ったか

EPUB という規格が生まれてから、CJK の縦書きについては長いあいだ、安定したサンプルも参照実装も乏しいままでした。結果として、本は各所のローカルルールや「試してみたらうまくいった方法」の寄せ集めで作られてきました。実際に世に出ている EPUB のタグを分析してみると、明らかにおかしい書き方をしているものが少なくありません。

そういう本を規格どおりに厳密に解釈すると、きれいに表示されません。**規格の正しさより「無難に表示されること」を優先したモード**があってもいいはずだ、というのがこのリーダーの出発点です。

同時に、逆向きの使い道も用意しました。おかしな body タグや CSS を書いている本は、**素直に崩れて見える**ようにもしてあります。うまくいっていない箇所がすぐ見つかる、簡易チェックツールとしても使えます。

## 2つの表示モード

### 読みやすさ優先（`friendly`・既定）

EPUB 側の指定の粗さを吸収して、「期待どおりの見え方」に寄せます。

- 画像を面いっぱいに表示する
- 画像だけのページ（表紙・口絵・章扉）はエンジンの列レイアウトに載せず直接描画し、Kindle 風に自動で見開きに組む
- SVG に包まれた表紙の比率を是正する（`preserveAspectRatio="none"` で潰れている本を直す）
- 縦書き指定が欠けている本を、EBPAJ 由来のクラスや OPF の `primary-writing-mode` から推測して補う

Kindle 出版のお手伝いを何度かやったことがあるのですが、その過程で「とりあえず無難に見えるビューアがある」ことの価値を実感しました。EPUB の技術に詳しくない書き手にとって、改ページの位置ひとつが不安の種になります。**「これはプレビューなので、最終的な見え方はプラットフォームごとに変わります」と言えるツール**があると、話が早いです。

### EPUB のまま（`raw`）

補正を全部止めて、EPUB に書いてある指定どおりにエンジンが描いた姿を見ます。歪んだ表紙も、効いていない指定も、そのまま出ます。作った EPUB のどこが破綻しているかを確かめる用途です。

配色・文字サイズ・行間・ユーザー CSS は `raw` でも効きます（これらは読書のための設定であって、EPUB の解釈ではないため）。

## 測定オーバーレイ

画面の上にルーラーと 16 色のカラーバーを重ねる機能があります。10px 刻みのセルを色で符号化してあるので、位置ずれやはみ出しが目で見て、かつ数値で読み取れます。

デバッグ専用にするつもりでしたが、**AI と組み合わせると非常に効率がいい**ことが分かったので、画面に重ねるグリッドはリリースビルドにも残しました（リーダー上部のツールバーから切り替えます）。

さらに DEBUG ビルドでは、同じ配色の計りレイヤーを本文の WebView に直接注入し、後述の MCP サーバー経由で座標を数値のまま取り出せます。HTML/CSS の不具合を AI に探させるときはこちらを使ってください。かなり速く見つかります。

## 読み上げ

自分で電子出版をやったとき、原稿をチェックする最高の方法は**読み上げソフトと組み合わせること**でした。まして今は一日中画面を凝視している生活です。趣味で小説も書きますが、発表前に何もかも目を皿のようにして確認するのは現実的ではありません。そういうわけで、読み上げにはかなり力を入れています。

- VOICEVOX / AivisSpeech による高品質な音声
- 再生速度、改行での待ち時間の調整
- ダブルクリックした箇所から読み上げ

### レイヤー優先度つきの読み辞書

日本語の TTS では、**短い語から優先してマッチする**という挙動が問題になります。たとえば「斎」1文字の読みを変更すると、「斎藤」のような熟語まで巻き込まれて変な読みになってしまいます。

読み上げエンジン側のユーザー辞書にはこれを制御する仕組みがないので、**語ごとに優先順位（レイヤー 1〜10）を持つ読み辞書をアプリ内蔵で実装**しました。大きいレイヤーから順に置換し、置換済みの部分は下のレイヤーでは触りません。「斎藤ひとし」を「斎」より上のレイヤーに置けば、1 文字の語に壊されなくなります。

正規表現による置換（`第(\d+)話` のようなパターン）にも対応しています。

## 書き出し

- **章ごとの音声ファイル書き出し** — 通勤電車で自分の書いた小説を聴く、グループで作っている作品を隙間時間でチェックする、といった使い方ができます
- **朗読動画の書き出し** — 読んでいる箇所だけが発光する縦書きの朗読動画を MP4 で出力します。録画ソフトも動画編集ソフトも要りません。自分の作品を YouTube に上げるのが手軽になります

朗読動画の生成部分は、ブラウザ単体で動くツールとしても `narration-video/` に分離してあります。

## 開発者向け：computer-use に頼らない E2E 自動テスト

このプロジェクトは、**MCP を使ったエンドツーエンドの自動テスト**をコンセプトの一つとして作られています。GUI アプリのテスト自動化に興味がある方には、実際に動く小さなサンプルとして参考になると思います。

- **座標クリックを使わない** — Accessibility(AX) API で UI 要素を名前で引いて操作します。スクリーンショットの目視にも、前面化にも、通知センターの被りにも依存しません
- **アプリ内テストバス** — DEBUG ビルドに JSONL over TCP のコマンドサーバーを内蔵（`TestBus.swift`）。UI からは辿りにくい状態変更や検証をコマンド一発でできます
- **数値でアサートする** — 「ずれて見える」ではなく、`ui_overflow` で「このボタンは枠から右へ 12.3pt はみ出している」と数値で判定します。目視スクショに頼りません
- **1 テストが数秒で終わる**

この手法自体の解説は `docs/` に置いてあります。

- [`docs/layout-qa-methodology.md`](docs/layout-qa-methodology.md) — 既知寸法の基準フィクスチャ＋プログラム測定＋数値アサートという考え方
- [`docs/measurement-overlay-technique.md`](docs/measurement-overlay-technique.md) — WebView に計りレイヤーを注入して測る技法
- [`mcp/epub-test-mcp/`](mcp/epub-test-mcp/) — MCP サーバー本体（Python・外部依存なし）
- [`test-assets/ruler/`](test-assets/ruler/) — 四辺に目盛りを焼き込んだ測定用 EPUB

## ダウンロード

ビルド済みのアプリを [Releases](https://github.com/veltrea/tategaki-reader/releases) に置いてあります。ZIP を展開して `EpubReaderSpike.app` を `/Applications` へ入れてください。

Apple Developer アカウント（年 $99）を使わない **ad-hoc 署名**なので、初回だけ macOS の警告を越える操作が要ります。

1. **右クリック →「開く」**（ダブルクリックでは開けません）→ もう一度「開く」
2. あるいは システム設定 → プライバシーとセキュリティ →「このまま開く」
3. コマンドでよければ:

```bash
xattr -dr com.apple.quarantine /Applications/EpubReaderSpike.app
```

一度許可すれば以降はそのまま起動します（ad-hoc でも配布物の署名は固定なので、許可は保持されます）。notarize（Apple の公証）は付いていません。必要な方はフォークして各自の Developer ID で署名してください。

## ビルド

必要なもの: Xcode、[XcodeGen](https://github.com/yonaskolb/XcodeGen)

```bash
cd spike-readium
xcodegen generate
xcodebuild -project EpubReaderSpike.xcodeproj -scheme EpubReaderSpike \
  -destination 'platform=macOS,variant=Mac Catalyst' -derivedDataPath ./DerivedData build
open DerivedData/Build/Products/Debug-maccatalyst/EpubReaderSpike.app
```

読み上げを使うには [VOICEVOX](https://voicevox.hiroshiba.jp/) を起動しておいてください。

```bash
curl -s http://127.0.0.1:50021/version
```

[AivisSpeech](https://aivis-project.com/) に切り替える場合は `VoicevoxTTSEngine.Config` の baseURL を `:10101` にします。
